## Add a robot cell

Open the {{ui:Robot cell}} section beside {{ui:Material flow}}. Choose a robot, then {{ui:Add robot cell}}. Three starters are included: a 4-axis SCARA, a generic 6-axis articulated arm (about 0.85 m) and a delta picker. Set where the robot's base stands (x, y, z and turn) and the tool length.

## Check the reach

The list shows every station, buffer, source and sink in the layout and whether the robot's tool can reach the middle of its top, and the point 0.1 m above it. "Not reachable" says why: too far or too close, outside a joint or height limit, or the tool cannot point straight down there. The arm and SCARA are solved from their joint geometry; the delta from its published arm geometry.

## Write and run a program

The program is plain text. The first line is `CCROBOT 1`. Then:

- `point NAME x y z` names a point in metres (stations in the layout are already named by their id).
- `speed N` sets the speed to N percent (1 to 100) of every limit.
- `movej NAME` moves all joints together to a point; `movel NAME` moves the tool in a straight line.
- `pick NAME` and `place NAME` come down from 0.1 m above, grip or release for 0.3 s and go back up. Add `clear 0.15` or `grip 0.5` to change those.
- `wait S` waits S seconds; `home` returns to the home pose.

{{ui:Sample program}} writes a pick at the first station and a place at the second. {{ui:Run program}} gives each step's time and the cycle time. {{ui:Use cycle time as station time}} sets a station's process time to that cycle, so the flow simulation uses it. {{ui:Save program text…}} and {{ui:Save path list (CSV)…}} write files.

## Pick the robot model

{{ui:Robot model}} lists generic robots (6-axis, long-reach 6-axis, SCARA, long SCARA, delta, Cartesian gantry) and one with published figures: a 6-axis arm with the UR5e's printed Denavit-Hartenberg rows and datasheet ranges. Only numbers that two public pages print are used; no CAD and no controller data. Open {{ui:Robot joint table (editable)}} to change the rows (arms) or the lengths and ranges (SCARA, delta, Cartesian). Changes are saved with the document.

## Choose the program formats

{{ui:Program formats}} has one checkbox per format. The path list (CSV and JSON) is always saved. Tick any of the others, set the {{ui:Gripper output number}}, and press {{ui:Save selected files…}}: the program is run and one file is saved per ticked format. Your choice is kept with the document and remembered as your default.

- **ROS URDF** is the robot itself (links, joints, limits from the table, the base placed in the layout). It needs a tree robot, so a delta is refused. Effort is a placeholder; there are no meshes or masses.
- **ROS joint trajectory** is the run as a JointTrajectory message in JSON: joint positions against time, straight moves sampled about every 5 cm. Signals are not part of that message.
- **Universal Robots URScript** needs a 6-axis arm. It writes joint and straight moves with speeds, digital outputs, waits for inputs and sleeps. It does not set a tool or frame (set the tool centre point on the controller to the tool length shown at the top of the file) and does not blend.

Every robot-language file starts with a comment saying it was generated by CadCraft, must be simulated and verified on your robot controller before it is run, and is not endorsed by the vendor. CadCraft has not run these programs on a robot. Joint values are those of the model's table: they are right for a real robot only if its zero positions and base frame match. A format refuses what it cannot say (a delta in URDF, a SCARA in URScript, a signal number it cannot address) and tells you why. {{ui:Sources and formats left out}} lists the public pages each syntax was read from, with the date, and the languages that are not offered (ABB RAPID, KUKA KRL, Fanuc, Yaskawa, Kawasaki, Mitsubishi, Staubli, Denso) with the reason: a language is added only when two independent public sources confirm the statements it needs.

Extra program words: `out 3 on` sets signal 3, `waitin 2 off` waits for input 2.

## What is not supported

- **Robot makers' files are not read.** Only the formats listed above are written; no RAPID, KRL, TP or similar, and no program from another offline-programming product.
- **No collision checking**, no tool or payload, no dynamics (a joint's speed and acceleration limits give the time). Times are a planning estimate, not a controller's number.
- The 6-axis arm uses a numeric solver and the tool pointing straight down; other tool angles are not yet offered. The delta cannot do straight-line moves through its singular edges, and its home is the middle of its working height.
- Vendor programs are minimal and not tested on a robot.
