## USD (.usd, .usda, .usdc, .usdz)

ဖွင့်ခြင်း၊ သွင်းခြင်း၊ နှင့် {{ui:Save as}} သို့မဟုတ် {{ui:Export}} › {{ui:USD (.usda, .usdc, .usdz)…}}။ ModelCraft သိမ်းထားသော USD ဖိုင်သည် ဘာမျှ မဆုံးရှုံးဘဲ ပြန်ဖွင့်နိုင်သည်; အခြားပရိုဂရမ်များ၏ USD ဖိုင်များကို mesh၊ အုပ်စု၊ အစိတ်အပိုင်း၊ မီးနှင့် ကင်မရာများအဖြစ် ဖွင့်သည်။ [USD ကို သိမ်း၊ ဖွင့်နှင့် ပို့ရန်](topic:usd) ကို ကြည့်ပါ။

## Collada (.dae)

သွင်းခြင်းနှင့် ပို့ခြင်း။ အခြား 3D modeler များနှင့် မော်ဒယ်လဲလှယ်ရန် အကောင်းဆုံး ဖော်မတ်။

- **ပို့ခြင်း:** Collada 1.4.1၊ Z အပေါ်၊ မီတာ။ အုပ်စု သို့မဟုတ် အစိတ်အပိုင်း အဓိပ္ပာယ်တစ်ခုလျှင် ဂျီသြမေတြီ တစ်ခု; အစိတ်အပိုင်းများကို တစ်ကြိမ်သာ ရေးပြီး ကိုးကားချက်ဖြင့် နေရာချထားသဖြင့် မျှဝေထားဆဲ ဖြစ်သည်။ အပေါက်ပါသော သို့မဟုတ် အတွင်းကွေးသော နယ်နမိတ်ရှိ မျက်နှာပြင်များကို တြိဂံများအဖြစ် ခွဲသည်။ အရောင်များသည် ပစ္စည်းများဖြစ်လာသည်။ ကပ်လျက်မဟုတ်သော အနားများကို မျဉ်းများအဖြစ် ရေးသည်။ ဖော်မတ်တွင် မှန်ကန်မှုမရှိသော အမည်များကို ညှိပြီး တိကျသော အမည်ကို ဘေးတွင် ထိန်းထားသည်။
- **သွင်းခြင်း:** တြိဂံများ၊ ပိုလီဂွန်များ (အပေါက်ပါ)၊ တြိဂံ fan နှင့် strip များသည် မျက်နှာပြင်များဖြစ်လာသည်; မျဉ်းများသည် အနားများဖြစ်လာသည်။ node transform၊ ဖိုင်၏ up axis နှင့် ယူနစ်ကို အသုံးပြုသည်။ နေရာများစွာတွင် ထားသော node သို့မဟုတ် node များစွာသုံးသော ဂျီသြမေတြီသည် အစိတ်အပိုင်းအဖြစ် ဝင်လာသည်; အခြား node များသည် အုပ်စုများအဖြစ် ဝင်လာသည်။ ပစ္စည်းအရောင် (diffuse) သည် မျက်နှာပြင်အရောင် ဖြစ်လာသည်။
- **မသွင်းရသော:** texture များ၊ skin နှင့် morph များ၊ ကင်မရာများ၊ မီးများ၊ transform အမျိုးအစား အချို့ (look-at နှင့် skew)၊ အခြားဖိုင်များသို့ ကိုးကားချက်များ။ အခြေအနေဘားက ၎င်းတို့ကို ရေတွက်ပြသည်။
- **ပို့ချိန်တွင် ဆုံးရှုံးသည်:** အနားများ မည်သည့်အနား ပျော့သည်။ **သွင်းချိန်တွင်** တြိဂံဖြစ်နေသော မျက်နှာပြင်များသည် တြိဂံအဖြစ် ဆက်နေပြီး၊ ပြားချပ်ဧရိယာများကို တစ်ခုတည်းသော မျက်နှာပြင်အဖြစ် ဖတ်ရန် ဖြတ်ကြိုးများကို ပျော့ပြောင်းစေသည်။

## OBJ (.obj, .mtl)

သွင်းခြင်းနှင့် ပို့ခြင်း။

- **သွင်းခြင်း:** `.obj` ကို `.mtl` နှင့် texture ပုံများနှင့်အတူ ချပါ (သို့မဟုတ် `.obj` တစ်ခုတည်းသွင်းပါ: ပစ္စည်းမပါဘဲ ဝင်လာပြီး၊ အခြေအနေဘားက လိုချင်သော `.mtl` ကို အမည်ပေးသည်)။ Y အပေါ်ဖြင့် မီတာအဖြစ် ဖတ်သည်။ object တစ်ခုစီ (`o`၊ မဟုတ်ပါက `g`) သည် [Mesh](topic:meshes) ဖြစ်လာပြီး၊ မျက်နှာပြင်များ ၎င်းတို့အတိုင်း ထိန်းထားသည် (quad များသည် quad အဖြစ်ပင် နေသည်)။ Texture coordinate၊ normal နှင့် per-vertex အရောင်များကို ထိန်းထားသည်။ ပစ္စည်း၏ အရောင်ပုံ (`map_Kd`၊ PNG၊ JPEG သို့မဟုတ် WebP) သည် scale နှင့် offset ရွေးချယ်မှုများဖြင့် texture အဖြစ် ဝင်လာသည်; မဟုတ်ပါက အရောင် (`Kd`)။ ဖိုင်၏ normal များ ပြတ်သည့် အနားများသည် hard ဖြစ်သည်; normal မရှိပါက ဖိုင်၏ smoothing group များက ဆုံးဖြတ်သည်။ အခြား map များ (bump၊ normal)၊ point၊ line နှင့် curve များကို ရေတွက်ပြီး ချန်ထားသည်။ OBJ တွင် ယူနစ် မရှိသဖြင့် မီလီမီတာ သို့မဟုတ် လက်မဖြင့် ပြုလုပ်ထားသော မော်ဒယ်သည် မှားသော အရွယ်အစားဖြင့် ရောက်လာသည်: သွင်းပြီးနောက် scale လုပ်ပါ ([Rotate and scale](topic:rotate-scale#fix-an-import-that-came-in-the-wrong-size) ကို ကြည့်ပါ)။
- **ပို့ခြင်း:** မီတာ၊ Y အပေါ်၊ ကမ္ဘာ coordinate များ။ အုပ်စုနေရာချထားမှုတစ်ခုလျှင် object တစ်ခု; အစိတ်အပိုင်းများကို နေရာတိုင်းတွင် အပြည့်အစုံ ရေးသည်။ Mesh များသည် ၎င်းတို့၏ မျက်နှာပြင်များ၊ texture coordinate များနှင့် normal များကို ထိန်းထားသည်; [ပျော့သော အနားများ](topic:soften) ဖြင့် ဆက်စပ်ထားသော မျက်နှာပြင်များသည် ထောင့်တစ်ခုစီအတွက် normal ရသည်။ မော်ဒယ်တွင် အရောင်ရှိလျှင် `.mtl` သည် `.obj` ဘေးတွင် ဒေါင်းလုဒ်ဆွဲသည်။ သွင်းထားသော texture ရှိလျှင် `.obj`၊ `.mtl` နှင့် ပုံများသည် `.zip` တစ်ခုအဖြစ် အတူ ဒေါင်းလုဒ်ဆွဲသည်။
- **ကန့်သတ်ချက်:** vertex သို့မဟုတ် မျက်နှာပြင် 2 သန်း; စာသား 64 MB။

## glTF (.glb, .gltf)

သွင်းခြင်းနှင့် ပို့ခြင်း၊ glTF 2.0။

- **သွင်းခြင်း:** `.glb`၊ သို့မဟုတ် `.gltf` ကို ၎င်း၏ `.bin` နှင့် texture ဖိုင်များနှင့်အတူ: ၎င်းတို့အားလုံးကို မြင်ကွင်းပေါ် တစ်ချိန်တည်း ချပါ (သို့မဟုတ် `.glb` ကို ရွေးပါ)။ `.gltf` ကို တစ်ခုတည်း ပေးလျှင် လိုအပ်သော ဖိုင်ကို အမည်ပေးသည်: "ဤ .gltf ဖိုင်သည် "…" ကို လိုအပ်သည်: .glb ဗားရှင်းကို ဖွင့်ပါ၊ သို့မဟုတ် .gltf ကို ၎င်း၏ဖိုင်များနှင့်အတူ ချပါ။"
  - **Mesh များ** သည် ဖိုင်တွင် mesh တစ်ခုလျှင် [Mesh](topic:meshes) တစ်ခုအဖြစ် ဝင်လာပြီး၊ ဖိုင်၏ normal၊ texture coordinate နှင့် vertex အရောင်များကို ၎င်းတို့တွင် ထိန်းထားသည်။ ဖိုင်၏ normal ပြတ်သော အနားများသည် hard ဖြစ်သည်; ကျန်သည်များ soft ဖြစ်သည်။ နေရာများစွာတွင် သုံးသော mesh သည် မျှဝေထားဆဲ ဖြစ်သည်။
  - **Node များ** သည် ဖိုင်တွင်ရှိသည့်အတိုင်း အမည်ပေးထားသော အုပ်စုများ ဖြစ်လာသည်။ Instanced mesh (EXT_mesh_gpu_instancing) များသည် mesh တစ်ခုအဖြစ် နေရာများစွာတွင် ထားသည်။
  - **ပစ္စည်းများ:** base color texture (PNG၊ JPEG သို့မဟုတ် WebP) သည် texture အဖြစ် ဝင်လာပြီး၊ ဖိုင်၏ texture coordinate (texture transform ပါလျှင် ထို့နောက်) ဖြင့် နေရာချထားသည်၊ သိမ်းသောအခါ ထိန်းထားသည်; မဟုတ်ပါက base color။ Metal၊ roughness၊ normal map၊ glass၊ clear coat၊ sheen နှင့် အခြား ပစ္စည်း extension များကို ဖတ်သော်လည်း ထိန်းထားခြင်း မရှိသေးပါ: အခြေအနေဘားက ထိုသို့ ပြောသည်။
  - **မီးများ** (KHR_lights_punctual): point နှင့် spot မီးများသည် [မီးများ](topic:lights) ဖြစ်လာသည်။ Directional မီးများကို ရေတွက်သည်: နေက မော်ဒယ်ကို ထိုးထိုးသည်။
  - **ကင်မရာများ** သည် [scene](topic:scenes) ဖြစ်လာသည်။
  - **Skin ပါသော ဇာတ်ကောင်များ** သည် ဖိုင်က ထားသည့်အတိုင်း ရပ်ဝင်လာသည်; ၎င်းတို့၏ bone နှင့် animation များ၊ morph target များကို ရေတွက်ပြီး ထိန်းထားခြင်း မရှိသေးပါ။
  - **ချုံ့ထားသော ဖိုင်များ** (Draco၊ meshopt) နှင့် quantized ဒေတာကို ဖတ်သည်။ Decoder များသည် လိုအပ်သော ဖိုင်အတွက်သာ တင်သည်။
  - Point နှင့် line များကို ရေတွက်ပြီး ချန်ထားသည် (mesh တွင် မျက်နှာပြင်များသာ ရှိသည်)။ KTX2 texture များကို ချန်ထားသည်; မျက်နှာပြင်များသည် အရောင်ကို ထိန်းထားသည်။
- **ပို့ခြင်း** (`.glb`): glTF 2.0 binary၊ မီတာ၊ Y အပေါ်။ definition တစ်ခုလျှင် mesh တစ်ခု၊ ထို့ကြောင့် အစိတ်အပိုင်းများ မျှဝေထားဆဲ။ Mesh များသည် ၎င်းတို့၏ normal၊ texture coordinate နှင့် vertex အရောင်များကို ထိန်းထားသည်; [ပျော့သော အနားများ](topic:soften) ဖြင့် ဆက်စပ်သော မျက်နှာပြင်များသည် ချောမွေ့သော normal ကို သယ်သည်။ အရောင်နှင့် ပစ္စည်းများသည် material ဖြစ်လာသည် (ပစ္စည်းတစ်ခုကို အရောင်အဖြစ်); သွင်းထားသော texture များကို texture အဖြစ် ရေးသည်။ ဖွင့်ထားသော မီးများသည် point နှင့် spot မီးများ ဖြစ်လာသည် (area မီးများကို glTF နှင့် တူညီမှု မရှိ၍ ချန်ထားသည်); scene များသည် ကင်မရာများ ဖြစ်လာသည်။ Loose edge များကို ချန်ထားသည်။
- **ကန့်သတ်ချက်:** ဖိုင် 300 MB အထိ; ဂျီသြမေတြီ နံပါတ်ပေါင်း 130 သန်းခန့်အထိ။

## STL (.stl)

သွင်းခြင်းနှင့် ပို့ခြင်း။

- **သွင်းခြင်း:** binary သို့မဟုတ် ASCII။ STL တွင် ယူနစ် မရှိ: **မီလီမီတာ** အဖြစ် ဖတ်သည်၊ ပရင်တာများနှင့် ModelCraft ကိုယ်တိုင်၏ ပို့ခြင်းက ရေးသည့်နည်းအတိုင်း။ တူညီသော အမှတ်ရှိ ထောင့်များကို ချိတ်သဖြင့် ပိတ်ထားသော အစိတ်အပိုင်းသည် ပိတ်ထားသော [Mesh](topic:meshes) အဖြစ် ဝင်လာသည်။ ဖိုင်ရှိ အရောင်များ (VisCAM / SolidView နှင့် Materialise စည်းမျဉ်းများ) သည် မျက်နှာပြင်များကို ဆေးသည်။
- **ပို့ခြင်း၊** 3D ပရင့်ထုတ်ရန်: binary STL၊ **မီလီမီတာ**၊ Z အပေါ်။ တြိဂံများသာ: အုပ်စုများနှင့် loose edge များကို ချန်ထားသည်။ ဆေးထားသော မျက်နှာပြင်များသည် VisCAM / SolidView စည်းမျဉ်းဖြင့် အရောင်ပါသည်၊ ဖတ်ခြင်းမရှိသော အခြားပရိုဂရမ်များက လျစ်လျူရှုသည်။ သန့်ရှင်းသော ပရင့်အတွက် ပိတ်ထားသော solid များကို ပို့ပါ။

## STEP (.step, .stp)

သွင်းရန်သာ။ STEP သည် ပါတ်ဆိုင်ပို့သူများနှင့် ပေးသွင်းသူများ ပို့သော ဖိုင်ဖြစ်သည်: AP203၊ AP214 နှင့် AP242 ဖိုင်များ။

- **သွင်းခြင်း:** ModelCraft သည် ဖိုင်ကို စာမျက်နှာအတွင်း ကိုယ်တိုင်ဖတ်ပြီး solid တိုင်းကို တြိဂံများဖြင့် ပိတ်ထားသော [Mesh](topic:meshes) အဖြစ် ပြောင်းသည်: ပြားချပ်မျက်နှာပြင်များ ပြားချပ်ဆဲ၊ ကွေးသော မျက်နှာပြင်များ (ဆလင်ဒါ၊ ကုန်း၊ စိုင်း၊ torus၊ B-spline မျက်နှာပြင်များ) သည် ပြားချပ်ငယ်များစွာ ဖြစ်လာသည်၊ ကွေးသော မျက်နှာပြင်တစ်ခုအတွင်းရှိ အနားများ ပျော့ပြီး မျက်နှာပြင်နှစ်ခုကြား အနားများ ထက်မြက်သည်။ STEP ဖိုင်များက ၎င်း၏ယူနစ်ကို ပြောသည်; မော်ဒယ်သည် မှန်ကန်သော အရွယ်အစားဖြင့် ဝင်လာသည်။ Assembly တစ်ခုသည် ဖိုင်က နေရာချထားသည့်အတိုင်း အစိတ်အပိုင်းတိုင်းနှင့် ဝင်လာပြီး၊ အစိတ်အပိုင်းတစ်ခုစီသည် ဖိုင်အမည်ဖြင့် အမည်ပေးထားသော အုပ်စုအတွင်း ကိုယ်ပိုင် Mesh ဖြစ်သည်။ အရောင်များ၊ assembly tree ၏ အစိတ်အပိုင်းအမည်များနှင့် tolerance (PMI) များကို မဖတ်ပါ။
- **မက်ဆေ့ချ်များ:** ကျော်ခဲ့သော သို့မဟုတ် ပိုကြမ်းစွာ ဆွဲထားသော အရာများကို အခြေအနေလိုင်းတွင် ("Notes: …") ထည့်သည်; solid မရှိသော ဖိုင်၊ ပျက်စီးသော ဖိုင် သို့မဟုတ် ကန့်သတ်ချက်ကျော်သော ဖိုင်သည် အကြောင်းပြကာ ဘာမျှ မထည့်ပါ။
- **ကန့်သတ်ချက်:** ဖိုင် 300 MB အထိ; မျက်နှာပြင် 400 000 နှင့် တြိဂံ 8 သန်း။

## .3dm

သွင်းရန်သာ။ `.3dm` ဖိုင်များတွင် NURBS မော်ဒယ်များ ပါသည်: polysurface၊ surface၊ mesh၊ curve နှင့် block များ။

- **သွင်းခြင်း:** ModelCraft သည် ဖိုင်ကို စာမျက်နှာအတွင်း ကိုယ်တိုင်ဖတ်သည်။ Mesh များသည် ၎င်းတို့အတိုင်း ဝင်လာသည်; polysurface သို့မဟုတ် extrusion ၏ မျက်နှာပြင်တိုင်းသည် ဖိုင်နှင့်အတူ သိမ်းထားသော render mesh မှ လာသည်၊ မဟုတ်ပါက ModelCraft က tessellate လုပ်သည် (ပလိန်း၊ NURBS မျက်နှာပြင်များ၊ revolution မျက်နှာပြင်များ၊ extrude ထားသော ကွေးမျဉ်းများ၊ extrusion များ; အနားများဖြင့် ဖြတ်ထားပြီး၊ ပိတ်ထားသော polysurface များသည် ပိတ်ထားသော mesh များ)။ ကွေးမျဉ်းများသည် အနားများ ဖြစ်လာသည်၊ block များသည် အစိတ်အပိုင်းများ ဖြစ်လာသည် (block အတွင်း block များ ထိန်းထားသည်)၊ layer များသည် tag များ ဖြစ်လာသည် (ပိတ်လျှင် ဝှက်ထား)၊ object ၏ အရောင် (ကိုယ်ပိုင်၊ layer ၏ သို့မဟုတ် ပစ္စည်း၏) သည် ၎င်း၏မျက်နှာပြင်များကို ဆေးသည်။ ဖိုင်က ၎င်း၏ယူနစ်ကို ပြောသည်; မော်ဒယ်သည် မှန်ကန်သော အရွယ်အစားဖြင့် ဝင်လာသည်။ အဆင့်ဆင့်လမ်းညွှန်: [.3dm မော်ဒယ် သွင်းရန်](topic:import-3dm-files)။
- **မက်ဆေ့ချ်များ:** အခြေအနေလိုင်းက သိမ်းထားသော mesh မှ မျက်နှာပြင်မည်မျှ လာသည်နှင့် tessellate လုပ်ထားသည်မည်မျှ ပြောပြပြီး၊ ချန်ထားခဲ့သော အရာများကို အမည်ပေးသည်: point၊ point cloud၊ စာသား၊ အတိုင်းအတာ၊ hatch၊ မီး၊ SubD object၊ ဖတ်ရန်မပြီးသေးသော မျက်နှာပြင်အမျိုးအစားများ၊ ချိတ်ထားသော block များ။
- **ကန့်သတ်ချက်:** ဖိုင် 300 MB အထိ။

## PLY (.ply)

အရောင်ပါသော mesh များအတွက် သွင်းခြင်းနှင့် ပို့ခြင်း (scan များ၊ အရောင်ဖြင့် 3D ပရင့်၊ အခြား modeler များ)။

- **သွင်းခြင်း:** ASCII နှင့် binary။ မျက်နှာပြင်များသည် ၎င်းတို့၏ normal၊ texture coordinate နှင့် vertex အရောင်များကို ထိန်းထားသော [Mesh](topic:meshes) ဖြစ်လာသည်; မျက်နှာပြင်တစ်ခုစီကို အရောင် 4,096 မှ အနီးဆုံးဖြင့် ဆေးသဖြင့် ယခု အရောင်များကို မြင်ရသည်။ PLY တွင် ယူနစ် သို့မဟုတ် ဝင်ရိုး စည်းမျဉ်း မရှိ: coordinate များသည် ရှိသည့်အတိုင်း ဝင်လာသည် (မီတာ၊ Z အပေါ်)။ အမှတ်များသာ ပါသော PLY သည် point cloud ဖြစ်သည်: BimCraft သို့မဟုတ် CivilCraft တွင် ဖွင့်ပါ။
- **ပို့ခြင်း:** binary PLY ဖြင့် အနေအထား၊ normal နှင့် အရောင်များ (မော်ဒယ်တွင် ရှိလျှင် texture coordinate များပါ)၊ မီတာ၊ Z အပေါ်။

## FBX (.fbx)

သွင်းရန်သာ။ FBX 7 ဖိုင်များ (2011 မှ စ၍)၊ binary သို့မဟုတ် ASCII၊ ModelCraft ၏ ကိုယ်ပိုင် reader ဖြင့် ဖတ်သည်။

- Mesh များသည် ၎င်းတို့၏ normal၊ texture coordinate (UV set အားလုံး) နှင့် vertex အရောင်များဖြင့် [Mesh](topic:meshes) ဖြစ်လာသည်; object အများအပြား သုံးသော mesh သည် မျှဝေထားဆဲ။ Object များသည် ၎င်းတို့၏ transform (pivot၊ offset နှင့် pre-rotation များပါ) ဖြင့် အုပ်စုများ ဖြစ်လာသည်။
- ပစ္စည်းများ: diffuse texture — ဖိုင်ထဲ ထည့်ထားသည် သို့မဟုတ် `.fbx` နှင့်အတူ ချထားသော ပုံ — သည် texture အဖြစ် ဝင်လာသည် (TGA ပုံများကို PNG အဖြစ် ထိန်းထားသည်); မဟုတ်ပါက diffuse အရောင်။ အခြား ပစ္စည်း ဆက်တင်များသည် ပစ္စည်းမော်ဒယ်အသစ်ကို စောင့်ဆဲ။
- ဖိုင်၏ up axis နှင့် ယူနစ်ကို အသုံးပြုသည်: အားလုံး Z အပေါ်၊ မီတာ ဖြင့် ဝင်လာသည်။
- Point နှင့် spot မီးများသည် [မီးများ](topic:lights) ဖြစ်လာသည် (FBX intensity 100 သည် ModelCraft ၏ ပုံမှန်မီး၊ 800 lumen ဖြစ်သည်: FBX intensity များတွင် ယူနစ် မရှိ)။ ကင်မရာများသည် [scene](topic:scenes) ဖြစ်လာသည်။
- Skin ပါသော ဇာတ်ကောင်များသည် rest အနေအထားဖြင့် ဝင်လာသည်; bone နှင့် animation များကို ရေတွက်ပြီး ထိန်းထားခြင်း မရှိသေးပါ။ Directional နှင့် area မီးများ၊ mesh မဟုတ်သော ဂျီသြမေတြီ (NURBS၊ curve) များကို ရေတွက်ပြီး ချန်ထားသည်။
- FBX 6 နှင့် အဟောင်းဖိုင်များကို ငြင်းပယ်သည်: FBX 2011 သို့မဟုတ် အသစ်ဖြင့် ပြန်သိမ်းပါ။

## Alembic (.abc)

သွင်းရန်သာ: အသက်ရှူ animation နှင့် effect ပရိုဂရမ်များမှ ဂျီသြမေတြီ cache များ။

- Mesh များ (polygon နှင့် subdivision mesh) သည် texture coordinate နှင့် normal ပါသော [Mesh](topic:meshes) ဖြစ်လာသည်; transform များသည် အုပ်စုများ ဖြစ်လာသည်။ Alembic သည် Y အပေါ်ဖြစ်ပြီး Z အပေါ်သို့ လှည့်သည်; မီတာ။
- Sample များစွာပါသော cache (animation) သည် ပထမ sample ဖြင့် ဝင်လာသည်; အခြေအနေဘားက ဘယ်နှစ်ခု ရှိသည် ပြောသည်။
- Point၊ curve၊ NURBS မျက်နှာပြင်များ၊ ကင်မရာများနှင့် မီးများကို ရေတွက်ပြီး ချန်ထားသည်။ ဟောင်းသော HDF5 အပြင်အဆင်ရှိ ဖိုင်များကို ငြင်းပယ်သည်: Ogawa Alembic ဖိုင်အဖြစ် ပြန်သိမ်းပါ။

{{ui:Check for 3D printing (STL or 3MF)…}} သည် ပုံသဏ္ဍာန်ကို ဦးစွာ စစ်ဆေးပြီး ရွေးထားသော အရာ သို့မဟုတ် မြင်ရသော အရာအားလုံးကို ရေးသည်။ [3D ပရင့်အတွက် မော်ဒယ် ပြင်ဆင်ခြင်း](topic:print-3d) ကို ကြည့်ပါ။

## 3MF (.3mf)

{{ui:Check for 3D printing (STL or 3MF)…}} မှ ပို့ခြင်းသာ။ 3MF core: **မီလီမီတာ** ဖြင့် mesh တစ်ခု၊ Z အပေါ်၊ အရောင်များကို ပစ္စည်းအဖြစ်။ Slicer အများစုက ဖတ်သည်၊ STL နှင့် မတူဘဲ ယူနစ်ကို ပြောသည်။ ဝှက်ထားသော အရာများကို ချန်ထားသည်။ [3D ပရင့်အတွက် မော်ဒယ် ပြင်ဆင်ခြင်း](topic:print-3d) ကို ကြည့်ပါ။

## DWG နှင့် DXF ပို့ခြင်း (.dwg, .dxf)

CAD ပရိုဂရမ်များအတွက်။ မော်ဒယ်ကို ၎င်း၏ကိုယ်ပိုင်ယူနစ်ဖြင့် ရေးသည်: ပေနှင့် လက်မ မော်ဒယ်များအတွက် လက်မ၊ မဟုတ်ပါက မီလီမီတာ၊ စင်တီမီတာ သို့မဟုတ် မီတာ (အခြေအနေဘားက အမည်ပေးသည်)။

- **မျက်နှာပြင်များ** သည် 3D မျက်နှာပြင် (တြိဂံများ) ဖြစ်လာသည်။ မျက်နှာပြင်အတွင်းရှိ မျဉ်းများနှင့် ပျော့သော အနားများကို မမြင်ရအောင် ရေးသည်၊ ထို့ကြောင့် မျက်နှာပြင်များသည် ModelCraft နှင့် တူသည်။
- **Loose edge များ** သည် မျဉ်းများ ဖြစ်လာသည်။
- **အုပ်စုများနှင့် အစိတ်အပိုင်းများ** သည် ဘလော့ခ်များ ဖြစ်လာသည်: အစိတ်အပိုင်းကို တစ်ကြိမ်ရေးပြီး သုံးသလောက် နေရာချထားသည်၊ လှည့်ထားသော နှင့် ထောင့်ပြန်ထားသော မိတ္တူများ အပါအဝင်။ လှည့်ပြီးနောက် ဆန့်ထားသော (ထောင်းနေသော) အုပ်စုကို နေရာတွင် ရေးသည်။
- **အရောင်များ:** DWG သည် မျက်နှာပြင်တစ်ခုစီ၏ အရောင်ကို တိတိကျကျ ထိန်းထားသည်; DXF သည် CAD စံအရောင် 255 မှ အနီးဆုံးကို သုံးသည်။
- **ဗားရှင်းများ:** DWG ကို AutoCAD 2004 (AC1018) အဖြစ် ရေးသည်၊ 2004 မှစ၍ CAD ပရိုဂရမ်များက ဖွင့်နိုင်သည်။ DXF သည် R12 (AC1009)၊ CAD ပရိုဂရမ်အားလုံး ဖတ်နိုင်သော ဗားရှင်း; R12 တွင် ယူနစ်အကွက် မရှိသဖြင့် CAD ပရိုဂရမ်အား မည်သည့်ယူနစ် သုံးမည်ကို ပြောပါ။
- **မရေးသော:** လမ်းညွှန်များ၊ အတိုင်းအတာများ၊ scene များနှင့် ကင်မရာ။

## IFC (.ifc)

ပို့ရန်သာ၊ BimCraft နှင့် အခြား BIM ပရိုဂရမ်များအတွက်။ IFC4 ဖြင့် ပရောဂျက်၊ ဆိုဒ်၊ အဆောက်အအုံနှင့် ၎င်း၏ထပ်များ။ အဆင့်မြင့်ဆုံး အုပ်စု သို့မဟုတ် အစိတ်အပိုင်းတိုင်းသည် အမည်ပါသော building element proxy တစ်ခု ဖြစ်လာသည်; ပိတ်ထားသည်များကို solid ပုံသဏ္ဍာန် (faceted brep) အဖြစ်၊ ဖွင့်ထားသည်များကို မျက်နှာပြင် မော်ဒယ်အဖြစ် ရေးသည်; မျက်နှာပြင်ပေါ် အပေါက်များကို ထိန်းထားသည်။ အဆင့်မြင့်ဆုံးအဆင့်ရှိ loose geometry သည် "Loose geometry" ဟု အမည်ရှိသော ဒြပ်စင် တစ်ခု ဖြစ်လာသည်။ အမျိုးအစား၊ ဂုဏ်သတ္တိ သို့မဟုတ် ပစ္စည်း မပါ။

**ထပ်များ:** {{ui:Export}} › {{ui:IFC storeys…}} သည် ၎င်းတို့ကို အမည်နှင့် အမြင့် (elevation) ဖြင့် စာရင်းပြသည် ({{ui:Add storey}}၊ သို့မဟုတ် {{ui:Guess from the model}}၊ ထိုသည် အဆင့်မြင့်အုပ်စုများ ရပ်နေသော အမြင့်တစ်ခုစီအတွက် ထပ်တစ်ခု ဖန်တီးသည်)။ ပို့ချိန်တွင် အုပ်စု သို့မဟုတ် အစိတ်အပိုင်းတိုင်းသည် အနိမ့်ဆုံးအမှတ်နှင့် ညီသော သို့မဟုတ် အောက်ရှိ ထပ်ပေါ် ရောက်ပြီး နေရာကို ထိန်းသည်။ ထပ်မရှိလျှင် အားလုံး "Level 1" (0 တွင်) ဟု အမည်ပေးသော ထပ်တစ်ခုတည်းပေါ် ရောက်သည်။ ထပ်များကို ModelCraft ဖိုင်တွင် သိမ်းထားသည်။

## DWG (.dwg) နှင့် DXF (.dxf)

မြေပြင်ပေါ်ရှိ မျဉ်းများအဖြစ် သွင်းခြင်း (hatch နှင့် 3D မျက်နှာပြင်များသည် မျက်နှာပြင်များ); အထက်ဖော်ပြထားသည့်အတိုင်း ပို့ခြင်း။ [Site plan တွင် မော်ဒယ်ဆွဲခြင်း](topic:site-plan) ကို ကြည့်ပါ။

- **ဖတ်ခြင်း:** မျဉ်းများ၊ polyline များ (အဝိုင်းပါ)၊ 3D polyline များ၊ စက်ဝိုင်းများ၊ အဝိုင်းများ၊ နှင့် block reference များ (array များပါ)၊ model space မှ။ မမြင်ရသော object များ (ဥပမာ dynamic block ၏ ဝှက်ထားသော အခြေအနေများ) ကို ချန်ထားသည်။ ကွေးများသည် လှည့်ပတ်တစ်ကျော့လျှင် မျဉ်းတိုအပိုင်း 48 ခု ဖြစ်လာသည်။
- **0.4 မှစ၍ ဖတ်ခြင်း:** spline နှင့် ellipse များ (အနားအဖြစ်)၊ စာသား၊ multiline စာသားနှင့် attribute တန်ဖိုးများ (တစ်ကြောင်းတည်း စာလုံးပုံစံဖြင့် အနားများအဖြစ်)၊ hatch များ (အပေါက်ပါ မျက်နှာပြင်များ)၊ 3D မျက်နှာပြင်များနှင့် solid fill များ (မျက်နှာပြင်များ)၊ နှင့် အတိုင်းအတာများ (ဒရော်ဝင်း၏ ကိုယ်ပိုင် dimension block များမှ ဆွဲထားသည်)။
- **0.7 မှစ၍ ဖတ်ခြင်း:** 3D solid၊ region နှင့် body များ (ACIS ဒေတာ၊ ဗားရှင်းတိုင်း၏ DWG နှင့် DXF)၊ ၎င်းတို့ကိုယ်ချင်းစီ အုပ်စုတစ်ခုစီ၊ ပိတ်ထားသည်များ solid ဖြစ်သည်။ ပလိန်း၊ ကိုယ်ထည်၊ ကုန်း၊ စိုင်း၊ torus နှင့် ရိုးရှင်းသော spline မျက်နှာပြင်များ မဟုတ်သော မျက်နှာပြင်များကို ချန်ထားပြီး စာရင်းပြသည်။
- **မဖတ်ခြင်း:** point များ၊ table များ၊ multileader များ၊ ပုံများနှင့် paper space ရှိ မည်သည့်အရာမဆို။
- **ယူနစ်များ:** ဒရော်ဝင်းက ပြောသည့်အခါ ဒရော်ဝင်းမှ ယူသည်။ မပြောလျှင် ModelCraft က မေးသည်။
- **DXF** သည် ASCII ဖြစ်ရမည်။ Binary DXF ကို ငြင်းပယ်သည်။
- **DWG** ဖိုင်များ AutoCAD R13 မှ လက်ရှိဖော်မတ် (AutoCAD 2018 နှင့် နောက်ပိုင်း; AC1012 မှ AC1032) အထိကို ModelCraft ၏ ကိုယ်ပိုင် DWG reader ဖြင့် ဖတ်သည်၊ စာမျက်နှာအတွင်း; ၎င်းသည် ModelCraft ၏ အစိတ်အပိုင်းဖြစ်သဖြင့် ModelCraft အလုပ်လုပ်သည့်အခါတိုင်း အော့ဖ်လိုင်းတွင်လည်း အလုပ်လုပ်သည်။ ဟောင်းသော ဗားရှင်းများ (R12 နှင့် ယခင်) နှင့် ပျက်စီးနေသော ဖိုင်များကို ဖတ်၍ မရပါ; DXF အဖြစ် သိမ်းပါ။
- **ကန့်သတ်ချက်များ:** မူလမှ 10,000 km ထက်ဝေးသော coordinate များ၊ သို့မဟုတ် မျဉ်းအပိုင်း 2 သန်းထက်ပိုသော ဖိုင်များကို ငြင်းပယ်သည်။

## SKP ဖိုင်များ

{{ui:Import}} (သို့မဟုတ် ဖိုင်ကို မြင်ကွင်းပေါ် ချပါ) သည် SketchUp ဖိုင်များကို ModelCraft ၏ ကိုယ်ပိုင် reader ဖြင့် စာမျက်နှာအတွင်း ဖတ်သည်: ဘာမျှ မတင်ပါ၊ ModelCraft အလုပ်လုပ်သည့်အခါတိုင်း အော့ဖ်လိုင်းတွင်လည်း အလုပ်လုပ်သည်။ SketchUp 3၊ 6၊ 7၊ 2014၊ 2017၊ 2018၊ 2020၊ 2025 နှင့် 2026 ဖိုင်များဖြင့် စမ်းသပ်ထားသည်; အခြားဗားရှင်းများလည်း ဖွင့်သင့်သော်လည်း မစမ်းရသေးပါ။ မော်ဒယ်သည် ဖိုင်အမည်ဖြင့် အမည်ပေးသော အုပ်စု တစ်ခုအဖြစ် ဝင်လာသည်။ {{key:Mod+Z}} တစ်ကြိမ်ဖြင့် ပြန်ဖယ်နိုင်သည်။ အဆင့်ဆင့် လမ်းညွှန်: [SKP မော်ဒယ် သွင်းရန်](topic:import-sketchup-files)။

- **ထိန်းထားသည်:** အပေါက်ပါ မျက်နှာပြင်များ၊ အုပ်စုများ (အုပ်စုအဖြစ်)၊ အစိတ်အပိုင်းများ (အစိတ်အပိုင်းအဖြစ်၊ မျှဝေထား)၊ ၎င်းတို့၏ အမည်များနှင့် နေရာချထားမှုများ၊ အရောင်များ၊ အုပ်စုနှင့် အစိတ်အပိုင်းများပေါ်ရှိ tag များ၊ မျက်နှာပြင်တစ်ခု၏ အစိတ်အပိုင်းမဟုတ်သော အနားများ၊ နှင့် ပျော့သော နှင့် ချောမွေ့သော အနားများ၊ ထို့ကြောင့် ကွေးသော မျက်နှာပြင်များ ချောမွေ့နေသည်။
- **အရောင်များ:** မျက်နှာပြင်၏ ကိုယ်ပိုင်ပစ္စည်းက အရောင်ပေးသည်။ အုပ်စု သို့မဟုတ် အစိတ်အပိုင်းပေါ် ဆေးထားသော ပစ္စည်းသည် ထိုနေရာချထားမှု၏ ဆေးဖြစ်လာသည်၊ ထို့ကြောင့် အတွင်းရှိ ကိုယ်ပိုင်အရောင်မရှိသော မျက်နှာပြင်များက ယူသည်၊ SketchUp ကဲ့သို့; အစိတ်အပိုင်းတစ်ခုကို အရောင်နှစ်ခုဖြင့် ဆေးထားလျှင် တစ်ခုတည်းသော အစိတ်အပိုင်းအဖြစ် ဆက်နေသည်။
- **Tag များ:** အုပ်စုနှင့် အစိတ်အပိုင်းပေါ်ရှိ tag များသည် ModelCraft tag များ ဖြစ်လာပြီး၊ ဖော်ပြထားသည်အတိုင်း ပြသခြင်း သို့မဟုတ် ဝှက်ခြင်း ဖြစ်သည်။ ကိုယ်ပိုင် မျက်နှာပြင်နှင့် အနားများပေါ်ရှိ tag များကို မထိန်းထားပါ (ModelCraft tag များသည် အုပ်စုနှင့် အစိတ်အပိုင်းများကိုသာ ထားသည်); အခြေအနေဘားက ရေတွက်သည်။
- **ဝှက်ထားသောအရာများ ဝှက်ထားသည့်အတိုင်း ဝင်လာသည်** (မျက်နှာပြင်များ၊ အနားများ၊ အုပ်စုများ၊ အစိတ်အပိုင်းများနှင့် ဝှက်ထားသော tag ပေါ်ရှိ မျက်နှာပြင်နှင့် အနားများ)၊ ထို့ကြောင့် SketchUp ပြခဲ့သည်ကို မြင်ရသည်; {{ui:Unhide all}} က ပြသည်။
- **Texture များ:** texture ပါသော ပစ္စည်းဖြင့် ဆေးထားသော မျက်နှာပြင်သည် ၎င်း၏ texture ကို ဖိုင်တွင်ရှိသည့်အတိုင်း ထားသည်၊ ModelCraft ဖိုင်က ပုံကို ထိန်းထားသည်။ အုပ်စု သို့မဟုတ် အစိတ်အပိုင်းတစ်ခုလုံးပေါ် texture၊ ဖိုင်တွင် မပါသော texture၊ သို့မဟုတ် browser မပြနိုင်သော ပုံ (ဥပမာ Photoshop ဖိုင်) သည် ၎င်း၏ပစ္စည်း၏ အရောင်ကိုသာ ထိန်းထားသည်။
- **ချန်ထားပြီး status bar တွင် ရေတွက်ထားသည်:** မော်ဒယ်ထဲ နေရာချထားသော ပုံများ။ စာသား၊ အတိုင်းအတာများ၊ လမ်းညွှန်များ၊ section အနားများ၊ scene များနှင့် style များကို မဖတ်ပါ။
- **ယူနစ်များ:** SketchUp ဖိုင်များသည် အတွင်းပိုင်း လက်မဖြင့် ဖြစ်သည်; ModelCraft က ပြောင်းပေးသဖြင့် အရွယ်အစားများသည် မည်သည့်ယူနစ်တွင်မဆို မှန်ကန်စွာ ထွက်သည်။
- **`.skp` ကို သိမ်းခြင်း** မရှိသေးပါ။ မော်ဒယ်ကို SketchUp သို့ ပြန်ယူရန် Collada (`.dae`) ကို ပို့ပါ။

## မထောက်ပံ့သောအရာများ

ModelCraft သည် 3DS သို့မဟုတ် IFC ဖိုင်များကို ဖွင့်၍ မရပါ၊ 3DS၊ FBX၊ STEP၊ `.3dm` သို့မဟုတ် SketchUp (`.skp`) ဖိုင်များကို သိမ်း၍ မရပါ။
